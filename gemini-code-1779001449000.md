## Роль и Задача (Task Overview)
Ты — опытный инженер-разработчик. Твоя задача — интегрировать клиент для работы с API Яндекс Маркета (Yandex Market Partner API) в нашу существующую систему. 

Интеграция должна быть бесшовной, расширяемой и написанной в том же стиле (архитектурные паттерны, линтеры, подходы к асинхронности), что и остальной код в репозитории.

## Функциональные требования (Features to Implement)
Реализуй модуль/сервис для работы со следующими эндпоинтами Яндекс Маркета (выбери нужные методы и удали лишнее):
1. [ ] Обновление остатков товаров: POST /campaigns/{campaignId}/offers/stocks
2. [ ] Обновление цен: POST /campaigns/{campaignId}/offer-prices/updates
3. [ ] Получение списка заказов (для модели FBS/DBS): POST /campaigns/{campaignId}/orders

## Архитектурные требования (Architecture Rules)
1. **Изоляция:** Создай отдельный сервис/класс (например, `YandexMarketClient` или `YandexMarketService`). Не смешивай логику запросов к API с бизнес-логикой приложения.
2. **Конфигурация:** Все конфиги (OAuth-токен, Campaign ID, Business ID) должны считываться строго из переменных окружения (.env / os.environ). Никаких хардкод-токенов в коде.
3. **HTTP-клиент:** Используй для запросов ту библиотеку, которая уже является основной в проекте (например, requests / httpx / aiohttp / HttpClient в C#). Если проект асинхронный — код интеграции тоже должен быть асинхронным.
4. **Обработка ошибок:**
   - Обрабатывай специфичные статус-коды Маркета (400, 401, 403, 423, 429, 500).
   - Предусмотри логику повторных запросов (retry mechanism) при ошибке 429 (Too Many Requests) или кратковременных сбоях сети.
   - Ошибки должны логироваться через стандартный логгер проекта, не роняя основное приложение.

## Ожидаемые изменения в репозитории (Expected Diffs)
- Новый файл/модуль клиента для Яндекс Маркета.
- Обновление существующих сервисов или фоновых задач (cron/worker), если требуется автоматический вызов созданных методов.
- Добавление необходимых DTO/моделей для валидации входящих и исходящих JSON-данных (если в проекте используется Pydantic / dataclasses / C# классы).
- [Опционально] Unit-тесты для нового клиента с использованием mock-запросов (не делай реальных запросов к API Маркета во время тестов).
