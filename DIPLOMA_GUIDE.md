# Руководство по структуре репозитория АИС «Гранит-Урал»

Данный документ содержит подробное описание всех файлов проекта для использования в дипломной работе. АИС «Гранит-Урал» — это информационная система для управления заказами, складскими остатками и автоматизации интеграции с маркетплейсами (на примере Яндекс Маркета).

---

## 1. Ядро приложения (`app/`)

В этой директории сосредоточена вся бизнес-логика, маршрутизация и работа с данными.

- **`__init__.py`**: Точка входа в пакет. Содержит фабрику приложений `create_app`, которая инициализирует Flask, подключает базу данных, регистрирует Blueprint-ы (модули) и настраивает глобальные обработчики ошибок.
- **`api.py`**: Реализация REST API. Содержит эндпоинты для программного взаимодействия с системой: получение списка товаров, создание заказов и запуск синхронизации с Яндекс Маркетом.
- **`auth.py`**: Модуль аутентификации. Отвечает за маршруты входа (`/login`) и выхода (`/logout`), а также управление сессиями пользователей.
- **`config.py`**: Централизованная конфигурация приложения. Считывает переменные окружения (из `.env`), настраивает параметры подключения к PostgreSQL и ключи доступа к API внешних сервисов.
- **`passwords.py`**: Утилиты для безопасного хранения паролей. Использует хеширование (pbkdf2_sha256) для проверки учетных данных без хранения паролей в открытом виде.
- **`repository.py`**: Слой доступа к данным (Data Access Layer). Реализует паттерн «Репозиторий». Содержит два класса:
    - `PostgresRepository`: для работы с реальной базой данных через SQL-запросы.
    - `InMemoryRepository`: для демонстрации и тестирования без развертывания БД.
- **`routes.py`**: Обработчики для веб-интерфейса (UI). Реализует рендеринг HTML-страниц: дашборд, реестр заказов, управление складом и просмотр логов аудита.
- **`security.py`**: Обеспечение безопасности и разграничение прав доступа (RBAC). Содержит декораторы `@login_required` и `@roles_required` для защиты маршрутов.
- **`services.py`**: Определение кастомных исключений (ошибки валидации, недостаток товара на складе), используемых во всем приложении.
- **`static/`**: Директория со статическими файлами (CSS, JavaScript, изображения). Здесь находятся стили Bootstrap и клиентские скрипты для интерактивности форм.
- **`templates/`**: Шаблоны HTML-страниц на движке Jinja2. Содержит структуру пользовательского интерфейса, разделенную по функциональным блокам (заказы, склад, аудит).
- **`yandex_market_client.py`**: Низкоуровневый клиент для работы с API Яндекс Маркета. Обрабатывает HTTP-запросы, авторизацию, лимиты (Rate Limiting) и повторные попытки при сбоях.
- **`yandex_market_models.py`**: Описание структур данных (DTO) для интеграции с маркетплейсом (остатки, цены).
- **`yandex_market_service.py`**: Высокоуровневый сервис интеграции. Реализует логику импорта номенклатуры, синхронизации остатков и автоматического создания заказов из маркетплейса в локальной системе.

## 2. База данных (`sql/`)

Директория содержит скрипты для развертывания и инициализации БД PostgreSQL.

- **`01_schema.sql`**: Определение структуры БД. Создает таблицы (users, products, orders, stocks), индексы, представления (view) и, что особенно важно, триггеры для автоматического ведения журнала аудита изменений.
- **`02_seed.sql`**: Скрипт первичного наполнения. Создает демонстрационных пользователей с разными ролями (Admin, Manager, Warehouse) и начальный каталог товаров.
- **`03_pgadmin_usage.sql`**: Примеры полезных SQL-запросов для администратора системы (мониторинг остатков, просмотр логов аудита напрямую в БД).

## 3. Тестирование (`tests/`)

Набор автоматизированных тестов для проверки корректности работы системы.

- **`conftest.py`**: Общие настройки для тестов и фикстуры (создание временных объектов приложения и репозиториев).
- **`test_order_flow.py`**: Проверка жизненного цикла заказа: от резервирования товара до успешной отгрузки или отмены.
- **`test_rbac.py`**: Тестирование ролевой модели доступа (проверка, что кладовщик не может создавать заказы, а менеджер не видит логи админа).
- **`test_yandex_market_client.py`**: Мок-тесты для API-клиента (проверка корректности формирования URL и заголовков).
- **`test_yandex_market_orders.py`**: Тесты интеграционной логики обработки заказов из внешних систем.

## 4. Файлы инфраструктуры и запуска

- **`.env.example`**: Шаблон файла с переменными окружения. Служит инструкцией по настройке доступа к БД и API.
- **`.gitignore`**: Инструкция для системы Git, указывающая, какие файлы и директории (например, `.env`, `__pycache__`) не должны попадать в репозиторий.
- **`.idea/`**: Конфигурационные файлы среды разработки (IDE) PyCharm/IntelliJ. Обычно игнорируются при развертывании.
- **`Dockerfile`**: Инструкция для сборки образа приложения в контейнере Docker.
- **`docker-compose.yml`**: Файл для оркестрации контейнеров. Позволяет запустить всё приложение вместе с базой данных одной командой.
- **`gemini-code-1779001449000.md`**: Техническое задание или заметки по реализации модуля интеграции с Яндекс Маркетом.
- **`requirements.txt`**: Список всех необходимых Python-библиотек (Flask, psycopg2, requests и др.).
- **`run.py`**: Основной скрипт запуска приложения (использует PostgreSQL).
- **`run_in_memory.py`**: Скрипт для быстрого запуска системы в демонстрационном режиме с хранением данных в оперативной памяти.
- **`README.md`**: Общая документация проекта, инструкции по установке и описание функциональных возможностей.
