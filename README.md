# Granit-Ural AIS

Централизованное веб-приложение на Flask/PostgreSQL для приема заказов, резервирования складских остатков, распределения по складам и обеспечения аудиторской прозрачности внутри операционной модели Granit-Ural.

## Технологический стек

- Backend: Python 3.x + Flask
- База данных: PostgreSQL под управлением pgAdmin 4
- Frontend: HTML5, Bootstrap 5, vanilla JavaScript
- Тестирование: pytest

---

# Функциональные возможности

- Управление заказами через веб-формы и REST-подобные API-эндпоинты
- Автоматическое резервирование товара при создании заказа для предотвращения перепродажи
- Панель управления складом для процессов комплектации, упаковки и отгрузки
- Ролевая модель доступа:
  - ADMIN: полный доступ, включая просмотр аудита
  - MANAGER: заказы, приоритеты, назначения отгрузки, отчеты
  - WAREHOUSE: управление остатками и выполнением отгрузки
- Аудит изменений на основе PostgreSQL-триггеров

# Инструкция по сборке базы данных (pgAdmin 4)

1. Откройте pgAdmin 4 и создайте базу данных с именем:

```text
granit_ural_ais
```

2. Откройте Query Tool для этой базы данных.

3. Выполните файл:

```text
sql/01_schema.sql
```

для создания таблиц, ENUM-типов, ограничений, триггеров, индексов и представления `v_inventory_status`.

4. Выполните файл:

```text
sql/02_seed.sql
```

для загрузки базовых пользователей, каталога товаров и складских остатков.

5. При необходимости выполните запросы из:

```text
sql/03_pgadmin_usage.sql
```

для повседневного мониторинга и контролируемого обслуживания.

# Примечания по базе данных

- Таблица `warehouse_stocks` хранит:
  - `on_hand_qty` — фактический остаток
  - `reserved_qty` — зарезервированное количество

- Резервирование выполняется в backend-транзакциях с использованием блокировок строк (`FOR UPDATE`) до записи изменений остатков.

- Аудит автоматически фиксируется для:
  - users
  - products
  - warehouse_stocks
  - orders
  - order_items
  - shipping_tasks

- Для привязки изменений, выполненных напрямую через pgAdmin, к конкретному пользователю необходимо установить `app.user_id` в рамках транзакции перед выполнением `UPDATE`.

# Инструкция по запуску приложения

## 1. Создайте виртуальное окружение

```bash
python -m venv .venv
```

## 2. Активируйте виртуальное окружение

```bash
.venv\Scripts\activate
```

## 3. Установите зависимости

```bash
pip install -r requirements.txt
```

## 4. Скопируйте `.env.example` в `.env` и настройте подключение к PostgreSQL

```env
FLASK_SECRET_KEY=change-me
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/granit_ural_ais
APP_PORT=5005
```

Если пароль PostgreSQL отличается от `postgres`, укажите параметры явно:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=granit_ural_ais
DB_USER=postgres
DB_PASSWORD=your_real_postgres_password
```

## 5. Запустите приложение

```bash
python run.py
```

## 6. Откройте в браузере

```text
http://127.0.0.1:5005
```

# Инструкция по проверке функциональности

## 1. Управление заказами

1. Войдите как `MANAGER`.
2. Откройте `/orders`.
3. Создайте новый заказ с одним или несколькими товарами.
4. Убедитесь, что заказ появился в реестре и получил статус `RESERVED`.

---

## 2. Автоматическое резервирование

1. Перед созданием заказа проверьте доступность товара на `/products`.
2. Создайте заказ на этот товар.
3. Вернитесь на `/products` и убедитесь, что:
   - `reserved_qty` увеличился
   - `available_qty` уменьшился

4. Попробуйте заказать больше доступного количества через форму или `POST /api/orders` — запрос должен завершиться ошибкой.

---

## 3. Панель распределения

1. Откройте `/dashboard`.
2. Под пользователем `MANAGER`:
   - измените приоритет заказа
   - назначьте задачу складскому сотруднику

3. Под пользователем `WAREHOUSE`:
   - откройте `/warehouse`
   - переведите заказ через статусы:
     - `PROCESSING`
     - `READY_TO_SHIP`
     - `SHIPPED`

---

## 4. Проверка RBAC

- `ADMIN` должен иметь доступ ко всем экранам, включая `/audit`
- `MANAGER` должен:
  - создавать заказы
  - изменять приоритеты
  - не иметь доступа к административному аудиту

- `WAREHOUSE` должен:
  - работать с остатками и задачами
  - получать `403 Forbidden` при попытке создания заказов менеджера

---

## 5. Аудит логов

1. Создайте или обновите заказ.
2. Войдите как `ADMIN`.
3. Откройте `/audit`.
4. Убедитесь, что в журнале появились:
   - INSERT/UPDATE для заказов
   - изменения строк заказа
   - изменения остатков
   - изменения задач отгрузки

# Эксплуатационные примечания

- Flask запускается на порту `5005` по умолчанию для обхода ошибки Windows `WinError 10013`, часто возникающей на порту `5000`.

- Слой `repository` использует только параметризованные SQL-запросы.

- Для production-развертывания:
  - размещайте Flask-приложение за WSGI-сервером
  - замените development secret key на надежный случайный ключ безопасности.
